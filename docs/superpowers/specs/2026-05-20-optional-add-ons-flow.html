Version Contract
// downlodr's package.json
"downlodrAddons": {
  "afda-backend": "1.2.0",
  "video-nemesis-toolkit": "1.0.3"
}
✓ Ready
Condition: installed version matches expected
Result: IPC handlers registered, features active
UI: Normal, no overlay
— Not Installed
Condition: package.json absent
Result: IPC handlers skipped
UI: Locked overlay, "Download Add-on"
⚠ Outdated
Condition: installed version doesn't match expected
Result: IPC handlers skipped
UI: Locked overlay, "Update Add-on"
When a new downlodr release ships a bug-fixed pack: bump version in downlodrAddons + upload new zip to Google Drive. On next launch, users in the "outdated" state are prompted to update automatically.
Storage Layout
AppData/Roaming/downlodr/ ← userData (persists across app updates)
  downlodr-add-ons/ ← all add-on packs live here
    afda-backend/
      dist/ ← compiled TypeScript
      node_modules/ ← native deps (better-sqlite3, playwright, etc.)
      package.json ← version checked on startup
    video-nemesis-toolkit/
      dist/
      node_modules/
      package.json
  temp/ ← download staging area, cleaned up after extraction

Open Questions for Discussion
1
Separate zips or one bundle? Should each pack be a separate download, or bundled into one "downlodr-add-ons-full.zip"? Separate is recommended — users only download what they need.
2
File IDs in package.json or separate config? Google Drive file IDs (and future GitHub release URLs) could live in package.json or a dedicated addons.config.json. Separate config keeps package.json clean.
