# VideoPlayerModal — Captions & Picture-in-Picture Design

**Date:** 2026-04-22
**Branch:** feat/video-player-embed
**Scope:** Add caption track support and native PiP float to `VideoPlayerModal`

---

## Overview

Two features added to the existing `VideoPlayerModal` component:

1. **Captions** — load a local VTT/SRT file as an HTML5 `<track>` element on the `<video>`, served via a `blob:` URL to work around Electron's `webSecurity: true` restriction
2. **PiP Float** — a button that calls `video.requestPictureInPicture()` and closes the modal, leaving the video playing in the OS-native floating overlay

---

## Props Changes

Two optional props added to `VideoPlayerModalProps`:

```ts
autoCaptionLocation?: string   // VTT/SRT downloaded by ytdlp (preferred)
transcriptLocation?: string    // SRT generated by Whisper (fallback)
```

Priority: `autoCaptionLocation` is used if present; `transcriptLocation` is used as fallback. Only one track is loaded at a time. If neither is present, no `<track>` is rendered.

---

## Caption Loading

### Why blob: URLs

`webSecurity: true` in `main.ts` blocks `<track src="file:///...">` from loading local files in the renderer. The solution is to read the file content via IPC, wrap it in a `Blob`, and create a `blob:` URL in the renderer.

### New IPC Method

Add `ytdlp.readCaptionFile(filePath: string): Promise<string>` across all 4 required touch points:

1. **`src/core-app/ipc/main/ytdlpHandler.ts`** — add `ipcMain.handle('ytdlp:readCaptionFile', ...)` that reads the file as UTF-8 text using `fs.readFile`
2. **`src/core-app/ipc/renderer/downlodrHandler.ts`** — expose `readCaptionFile: (path) => ipcRenderer.invoke('ytdlp:readCaptionFile', path)` on the bridge
3. **`src/global.d.ts`** — add `readCaptionFile(filePath: string): Promise<string>` to both `ytdlpFunctionsBridge` and `ytdlp` interface declarations
4. **`src/core-app/ipc/composeWindowApi.ts`** — wire `readCaptionFile: ytdlpBridge.readCaptionFile` into the `w.ytdlp` composed object

### Renderer Flow

Inside `VideoPlayerModal`, a `useEffect` dependent on `[isOpen, autoCaptionLocation, transcriptLocation]`:

1. Determines which path to use (`autoCaptionLocation ?? transcriptLocation`)
2. Calls `window.ytdlp.readCaptionFile(path)` — runs in parallel with the existing `getDirectUrl` call
3. Wraps the returned string in `new Blob([content], { type: 'text/vtt' })` (VTT and SRT both work under `text/vtt` in Chromium)
4. Calls `URL.createObjectURL(blob)` → stores in `captionBlobUrl` state
5. Cleanup revokes the blob URL via `URL.revokeObjectURL` when the modal closes

This triggers exactly one re-render to add `<track>` to the DOM. Adding a `<track>` to an existing `<video>` does not reload or interrupt playback.

### Rendering

```tsx
{directUrl && (
  <video ref={videoRef} src={directUrl} controls autoPlay ...>
    {captionBlobUrl && (
      <track
        key={captionBlobUrl}
        kind="subtitles"
        src={captionBlobUrl}
        srcLang="en"
        label="Captions"
        default
      />
    )}
  </video>
)}
```

## Picture-in-Picture Float

### Button Placement

A "Float" button added to the video overlay (top-right corner, inside the `relative` container). Hidden if `document.pictureInPictureEnabled` is `false`.

### On Click

```ts
const handleFloat = async () => {
  if (videoRef.current) {
    await videoRef.current.requestPictureInPicture();
  }
  onClose();
};
```

- `requestPictureInPicture()` hands the video to the OS PiP compositor
- `onClose()` unmounts the modal; blob URL cleanup runs via `useEffect` return
- Active `<track>` captions carry through to PiP automatically (Chromium passes text tracks to the OS overlay)

### No Extra State

PiP is fire-and-forget — no polling, no window sync, no IPC. The OS owns the floating window entirely.

## What Is Not in Scope

- Caption language selection or multi-track toggling
- Fetching remote captions from `automaticCaption` URLs
- Custom PiP UI controls
- Caption format conversion (SRT → VTT); Chromium handles both under `text/vtt`
