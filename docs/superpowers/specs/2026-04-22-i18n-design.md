# i18n Design — Downlodr Internationalization

**Date:** 2026-04-22  
**Status:** Approved  
**Packages:** `i18next@26.0.6`, `react-i18next@17.0.4`

---

## Goal

Make Downlodr's UI translatable into multiple languages. English remains the default and fallback. LTR languages only for now. Infrastructure should allow contributors to add new languages by adding a folder of JSON files.

---

## File Structure

```
src/
  locales/
    en/
      common.json       # shared strings: buttons, labels, generic errors
      downlodr.json     # download queue, history, context menus, modals
      skedulosa.json    # scheduled downloads UI
      settings.json     # settings modal
      plugins.json      # plugin manager UI
    es/                 # example of a future language — same shape as en/
      common.json
      downlodr.json
      ...
  core-app/
    i18n.ts             # i18next initialization, imported once in renderer.tsx
```

Namespaces map 1:1 to existing feature modules so contributors know where to find strings. Adding a language = copy `en/`, translate each file.

---

## i18next Initialization (`src/core-app/i18n.ts`)

- Locale JSON files are imported directly (no HTTP backend — Electron can import JSON at build time).
- Initialized with `initReactI18next` plugin so all React components can use `useTranslation`.
- `lng` is set at startup from the persisted Zustand `settingsStore.settings.language` value, falling back to `'en'`.
- `fallbackLng: 'en'` ensures untranslated keys fall back to English silently.
- `escapeValue: false` — React handles XSS escaping already.
- Namespaces: `['common', 'downlodr', 'skedulosa', 'settings', 'plugins']`, default namespace: `'common'`.

```ts
i18n.use(initReactI18next).init({
  resources: {
    en: { common, downlodr, skedulosa, settings, plugins }
  },
  lng: 'en',           // overridden at runtime from settingsStore
  fallbackLng: 'en',
  ns: ['common', 'downlodr', 'skedulosa', 'settings', 'plugins'],
  defaultNS: 'common',
  interpolation: { escapeValue: false }
});
```

The `i18n` instance is exported and imported in `renderer.tsx` (side-effect import) before the React tree mounts.

## Settings Integration

### `settingsStore.tsx`
- Add `language: string` field to `DownloadSettings` interface, default `'en'`.
- Add `updateLanguage(lang: string): void` action.
- Persisted automatically via existing IndexedDB persistence.

### `SettingsModal.tsx`
- Add a "Language" dropdown section.
- On change: call `i18n.changeLanguage(lang)` + `updateLanguage(lang)`.
- Initial list: `English (en)` only. More added as locale files are contributed.

### Startup sync
- In `renderer.tsx` (or a small hook), after the store rehydrates, call `i18n.changeLanguage(settings.language)` so the persisted preference is applied before first render.

## Component Migration Strategy

Migration is incremental — the app continues to work with any mix of migrated and unmigrated components.

### Per-component pattern
```tsx
import { useTranslation } from 'react-i18next';

const { t } = useTranslation('downlodr');
// replace: "Download"
// with:    {t('actions.download')}
```

### Migration priority order
1. **Navigation & TitleBar** — highest visibility, touches every page
2. **Settings modal** — users will look here for language controls
3. **Download module** — context menus, table headers, modals, status labels
4. **Skedulosa** — scheduled download UI
5. **Plugins** — plugin manager UI
6. **Remaining modals** — About, Help, Stop, Info

### Key naming convention
Keys use dot-notation scoped to their component context:
```json
{
  "actions": { "download": "Download", "cancel": "Cancel", "retry": "Retry" },
  "status": { "queued": "Queued", "finished": "Finished", "error": "Error" },
  "table": { "title": "Title", "size": "Size", "speed": "Speed" }
}
```

---

## Error Handling & Edge Cases

- **Missing key:** i18next logs a warning in dev and renders the key string — never blank UI.
- **Partial translations:** `fallbackLng: 'en'` fills in any untranslated keys automatically.
- **Store not yet rehydrated:** Default `lng: 'en'` in `i18n.init` ensures the app renders correctly before the persisted language is loaded.

---

## Out of Scope

- RTL language support (can be added later with CSS `dir` attribute)
- Auto-detection from OS locale (can be added later via `i18next-browser-languagedetector`)
- Translation management tooling / CI checks for missing keys
