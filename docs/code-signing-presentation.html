🚀 What is Auto-Update?

🔄

Seamless Updates

Users receive new versions automatically without manual downloads. The app checks for updates, downloads in background, and installs on restart.

🛡️

Security Critical

Auto-updates require code signing to verify authenticity. Without it, attackers could push malicious updates to all users.

📊

Industry Standard

Every major desktop application (Chrome, VS Code, Slack, Spotify, Cursor) uses signed auto-updates. It's expected by users.

📋 Complete Auto-Update Workflow

👨‍💻
Development
Code committed to version control with semantic versioning
🔨
Build
CI compiles for all platforms (Win, Mac, Linux)
🔏
Sign
Code signing with secure HSM or Key Vault
📦
Publish
Upload to release server with manifest
👥
Rollout
Staged release to users with monitoring
1

Version Bump & Changelog

Developer updates version in package.json, writes changelog, and creates a Git tag. This triggers the release pipeline.

2

Multi-Platform Build

CI/CD (GitHub Actions, Azure Pipelines) builds the app for Windows (NSIS/MSI), macOS (DMG), and Linux (AppImage/deb). Electron Forge or electron-builder handles packaging.

3

Code Signing (Critical Step)

Windows: Sign with EV certificate via SignTool + HSM/Azure Key Vault. macOS: Sign with Apple Developer ID + notarize with Apple's service. This step is REQUIRED for auto-updates to work.

4

Generate Update Manifest

Create latest.yml (Windows), latest-mac.yml (macOS) with version, file hashes, and download URLs. These manifests tell clients about new versions.

5

Upload to Release Server

Publish signed packages and manifests to GitHub Releases, S3, Azure Blob, or custom server. CDN caches files globally for fast downloads.

6

Client Checks for Updates

App periodically fetches manifest from update server (every hour, on launch, etc.). Compares server version with local version using semver.

7

Background Download

If update available, download in background. Support for resume on network failure. Verify file hash matches manifest.

8

Signature Verification

Before installing, OS verifies code signature. Windows: Authenticode verification. macOS: Gatekeeper + notarization check. Invalid signature = update rejected.

9

Install & Restart

User prompted to restart, or update installs silently on app quit. Old version replaced with new version. Rollback data kept for emergency recovery.

🔏 Why Code Signing is Required

🛡️

Prevent Man-in-the-Middle

Without signing, attackers on the network could intercept update downloads and replace them with malware. Signing proves the update is from you.

🖥️

OS Security Policies

Windows SmartScreen and macOS Gatekeeper block unsigned executables. Updates would fail or show scary "Unknown Publisher" warnings.

🔄

Updater Requirements

electron-updater verifies signatures before installing. Unsigned packages are rejected. This is a security feature, not a bug.

👥

User Trust

Professional software is signed. Unsigned apps appear suspicious and generate support tickets. Users expect seamless, silent updates.

🪟

Windows Requirements

SmartScreen: Blocks with "Windows protected your PC". Users must click "More info" → "Run anyway".

EV Certificate: Bypasses SmartScreen immediately. No reputation building needed. Required for professional deployment.

Authenticode: Windows verifies signature before allowing execution.

🍎

macOS Requirements

Gatekeeper: Completely blocks unsigned apps. No easy bypass for regular users.

Notarization: Even signed apps must be notarized (Apple scans for malware). Without it, Gatekeeper blocks.

Hardened Runtime: Required for notarization. Restricts debugging and code injection.

🚨 Security Risks Without Code Signing

1. Man-in-the-Middle Attack

Attacker on compromised network (coffee shop WiFi, ISP level, corporate proxy) intercepts update request and serves malware instead of legitimate update. All users on that network get infected.

2. Update Server Compromise

If your update server is hacked, attackers replace update files with malware. Without signing, users have no way to detect this. Entire user base potentially compromised.

3. DNS Hijacking

Attackers redirect your update domain to malicious server hosting fake updates. Even HTTPS doesn't fully protect against this. Only code signing proves authenticity.

4. Supply Chain Attack

Build pipeline or CI/CD compromise injects malicious code into legitimate builds. Code signing with HSM-protected keys helps detect unauthorized modifications.

💀
Real-World Examples

CCleaner (2017): Attackers compromised build server, distributed malware to 2.27 million users through official update channel.

SolarWinds (2020): Supply chain attack affected 18,000+ organizations including US government agencies.

ASUS Live Update (2019): Backdoored updates pushed to 1 million+ users through hijacked update mechanism.
