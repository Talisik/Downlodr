Route Tree

└─ SkedulosaRouteGuard redirects if no subscriptions
├─ /schedule SkedulosaSchedulePage INDEX
├─ /subscription SkedulosaSubscriptionPage
├─ /history SkedulosaHistoryPage

Sync Service

Bridges the core Downlodr queue ↔ Skedulosa store

SubscriptionDownloadSyncService — src/skedulosa/services/subscriptionDownloadSync.ts

Singleton
Usage: Import the singleton — import { subscriptionDownloadSync } from '…/subscriptionDownloadSync'. Never instantiate directly.
MethodParametersWhat it does
registerQueuedSubscriptionDownload
queueId: string
subscriptionId: string
downloadData: { name, displayName?, thumbnails?, size?, speed? }
 Called when a subscription triggers a new download. Stores a queueId→subscriptionId mapping for tracking.
onDownloadStarted
actualDownloadId: string
queuedDownload: QueuedDownload
 Fires when the core downloader picks up the queued item. Writes a new download entry to useSkedulosaStore with status 'initializing'.
syncDownloadStatus
downloadId: string
updates: { status?, progress?, speed?, size? }
 Syncs live progress to the Skedulosa store. Throttled 1000ms for progress/speed updates to avoid performance issues.
onDownloadCompleted
downloadId: string
status: 'finished' | 'failed'
 Marks the download as completed in the Skedulosa store. Not throttled — fires immediately.
cleanup
 — Clears all internal tracking maps. Call on app unmount.
Internal Architecture
Map 1: queueId → data
{ subscriptionId, downloadData }
Populated by registerQueued…
Consumed by onDownloadStarted
Map 2: downloadId → subscriptionId
O(1) lookup
Populated by onDownloadStarted
Used by syncStatus & onCompleted

Data Flow

Step-by-step walkthrough of the three main flows

① Add Subscription

User Action
Opens SkedulosaSubscribeModal
Fills: channelName, sourceURL, schedule days, time, quality, save path
Store Action
addSubscription(subscription)
skedulosaStore — persisted to IndexedDB
Auto Sync
scheduledChannels[] updated
Legacy ScheduledChannel derived inside store
UI Reacts
All pages re-render
RouteGuard unblocks, Schedule/Subscription/Stats all update

② Download Triggered

Scheduler
registerQueuedSubscriptionDownload
(queueId, subscriptionId, downloadData)
Core Downlodr starts
onDownloadStarted
(actualDownloadId, queuedDownload) → status: 'initializing'
Progress (throttled 1s)
syncDownloadStatus
(downloadId, { status, progress, speed, size })
Store Update
updateSubscriptionDownload
(subscriptionId, downloadId, Partial<Download>)
Completion
onDownloadCompleted
(downloadId, 'finished' | 'failed')

③ Read & Display

Select data
useSkedulosaStore(s => s.subscriptions)
or scheduledChannels for legacy pages
Filter
filterSubscriptionsByStatusAndCategory
(subs, statusFilter, categoryFilter)
Format for display
Pass through utils
formatBytesToHuman(getTotalStorageForDownloads(ch.downloads))
formatSchedule(entry) → "Every Monday 6:00 AM"
formatStatus(ch.status) → "Running"
Render
Page renders formatted data
Tables, charts, stat cards, heatmaps
